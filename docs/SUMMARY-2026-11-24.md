## 一、今日完成

### 1. 索尼 BLE 定位链路打通（A7R4 / A7M5）
- **扫描不到 A7R4**：mode22 广播里遥控位是 bit2（新代为 bit1），放宽匹配为
  bit1 | bit2 | bit5（定位位）
- **无法配对**：相机侧残留旧 bond / IRK 失效 → 设备使用固定随机身份地址
  （EFUSE MAC 异或 + 静态随机位），配合分区刷机保留 NVS 配对信息
- **位置写不进**：A7R4 不支持 dd30/dd31 使能流程，必须**直接写 dd11**
  95 字节坐标包，且连接前 **MTU 提到 158**
- 结果：A7R4、A7M5 照片 EXIF 均写入 GPS

## 二、关键技术结论

1. **ESP32-S3 三档频率不会打乱外设**：IDF `rtc_clk.c` 在 80/160/240 的 PLL 档位下
   硬编码 `rtc_clk_apb_freq_update(80 MHz)`，APB 恒为 80 MHz，GPS 串口 115200、
   PMIC I2C、LCD SPI、Flash 时序均不受影响；BLE 要求 CPU ≥ 80 MHz，满足。
2. **PM 锁方案不可行**：PM 给每个核常驻 `rtos0/rtos1` 两个 CPU_FREQ_MAX 锁，
   只要任务在跑 CPU 就钉在最高档。正确做法是 `esp_pm_configure(min=max)` 重配档位。
3. **刷机必须分区写入**（0x0 bootloader / 0x8000 partitions / 0x10000 app），
   合并镜像从 0x0 刷会把 NVS 配对信息覆盖成 0xFF。
4. **电量无电流计**：按 250 mAh 容量 / 典型 95 mA 折算剩余时间，待实测校准。
5. 日志里的 `APB_MAX: 240` 只是 PM 内部模式命名，硬件寄存器 APB 仍为 80 MHz。

    esptool --chip esp32s3 --port <PORT> write-flash \
      0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin

    cd gpscam && pio run -e sticks3
